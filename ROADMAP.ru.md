# План развития FlickVert

## Цель

FlickVert должен вызываться прямо во время работы с файлами в Проводнике или Finder, быстро показывать подходящие действия и сохранять результат рядом с исходником либо в выбранную папку. Обработка остаётся локальной.

## Что уже есть

- Tauri и Rust отвечают за системные события, доступ к файлам, безопасную запись результатов и запуск профильных конвертеров.
- React отвечает за компактное круговое меню и окно настроек.
- Обычные изображения обрабатываются средствами WebView; видео, аудио, RAW и часть документов передаются FFmpeg, ImageMagick, Pandoc, LibreOffice или Poppler, если они установлены.
- При установленном FFmpeg PNG-конвертация и JPEG→JPEG идут по пути файла через Rust, без передачи содержимого изображения через WebView.
- Небольшие изображения теперь могут обрабатываться по два одновременно. Большие файлы и внешние конвертеры остаются последовательными, чтобы ограничить память и не запускать несколько тяжёлых процессов без необходимости.

## Следующие этапы

### 1. Проверить основной жест на Windows и macOS

- Windows: проверить Shift + перетаскивание из Проводника, выбор сектора наведением и запись результата рядом с исходником.
- macOS: проверить Accessibility и Input Monitoring, перетаскивание из Finder и поведение при нескольких мониторах.
- Считать платформу готовой только после ручной проверки реального приложения на ней.

### 2. Измерить и ускорить обработку изображений

- Сравнить Canvas/WebView и нативный Rust-конвертер на одинаковом наборе файлов: небольшие изображения, большие фото и пакет из нескольких десятков файлов.
- Замерять полное время, пиковую память и размер результата; отдельно учитывать чтение, кодирование и сохранение.
- Перенести оставшиеся типы и действия в нативную обработку, только если измерения покажут выигрыш поверх текущего пути через FFmpeg.
- Сохранить правильную ориентацию EXIF, прозрачность, цветовой профиль, качество и защиту от перезаписи.

### 3. Сделать очередь понятной и управляемой

- Показывать имя текущего файла, прогресс пакета, успешные и неудачные результаты.
- Добавить отмену текущей операции и очереди; незавершённые временные файлы удалять.
- Разрешить повторный запуск только неудачных элементов, не создавая копии уже готовых результатов.
- Ограничивать параллелизм по типу операции и размеру файла.

### 4. Упростить запуск действий из системы

- Windows: пункт «Открыть с FlickVert» или отправка через контекстное меню/«Отправить».
- macOS: действие Finder Quick Action с установкой и удалением вместе с приложением.
- Оставить горячую клавишу и круговое меню быстрым способом для перетаскивания.

### 5. Упростить работу с движками и выпуском

- Показывать для каждого формата, какой движок нужен и установлен ли он.
- Позже добавить управляемую установку дополнительных движков с явным согласием, проверкой подписи и лицензии.
- Проверять чистую установку, обновление и удаление; подписывать сборки Windows и macOS перед публичным выпуском.

## Критерии готовности скорости

- Сравнение проводится на одном и том же тестовом наборе и устройстве.
- Параллельная обработка не вызывает резкого роста памяти и не мешает другим приложениям.
- Для каждого результата сохраняются исходник, формат, размер и время обработки; оригинал никогда не перезаписывается.
- Изменение считается ускорением только если оно уменьшает полное время без ухудшения качества и надёжности.

## Что не нужно переписывать

- Не переносить React-интерфейс на Rust ради скорости: меню и настройки не являются основным временем конвертации.
- Не заменять профильные медиадвижки самописными кодеками.
- Не включать неограниченную параллельную обработку.
- Не скачивать сторонние движки незаметно для пользователя.
